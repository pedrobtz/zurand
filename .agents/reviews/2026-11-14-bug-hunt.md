# zurand bug hunt, 2026-11-14

Commit `8a4c4eb`. Three hunters on Fable, run one at a time, each seeing
only its own brief. Their slices: the R layer; lifecycle (lazy vectors,
OpenMP state, fork, interrupts); the numeric core, C API and unbuilt
branches. The coordinator ran on Opus 5.5.

Built here:

- macOS x86_64, clang, serial (no OpenMP), AVX2, R 4.6.2.
- Linux in `ghcr.io/r-hub/containers/ubuntu-release`: gcc 15, OpenMP with
  4 threads, AVX2, R 4.6.1. Hunter 2 also made an ASan + UBSan build of a
  copy.
- Hunter 3 built the C core alone with the C99 `mulhilo64` forced, and
  with `-march=haswell -mfma -ffp-contract=fast`.

Unverified, so inspection only: NEON/arm64, i386, Windows, musl, macOS
with libomp.

Every finding below was re-run by the coordinator against a fresh install
of `8a4c4eb`, except #132 and #133, which were confirmed in the source.

## 1. Fork after a threaded fill hangs the children — #122, high (blocking), reproduced

- **Where:** every `#pragma omp parallel` in `src/zurand.c` (1411, 1424,
  1597, 1607, 1653, 1665, 1712) and in `src/zurand_engine.h`. Lazy
  vectors reach them through `lazy_region`, `lazy_materialise` and
  `lazy_unchanged`.
- **Trigger:** on Linux, `rng_normal(key, 32768)` in the parent, then
  `mclapply(1:2, function(i) rng_normal(key, 32768), mc.cores = 2)`. The
  children never return (`timeout 30` exits 124); the cold run passes.
  - A child that only *returns* a lazy vector the parent materialised
    also hangs: serialising it runs `lazy_unchanged()`'s threaded
    compare.
- **Cause:** GNU libgomp's pool does not survive `fork()`, and zurand has
  no `pthread_atfork()` handler or pid check.
- **Fix:** an atfork child handler that drops to one thread, as
  data.table does.
- **Family:** 2. **Siblings checked:** every parallel site and the three
  lazy paths. All hang at 32768 values or more; below the OpenMP
  threshold, children are fine.
- **Test the suite lacked:** a parent fill, then `mclapply()` fills and
  lazy returns inside `callr::r(timeout =)` on the OpenMP leg (#115).
- **Graded blocking:** a hang is not a wrong value, but
  `vignettes/zurand.Rmd:82` sells `mclapply()`, and every Linux user
  reaches this.

## 2. `rng_fold()` of a native non-ASCII string depends on the locale — #123, medium, reproduced

- **Where:** `src/zurand.c:1345`, `Rf_translateCharUTF8()`.
- **Trigger:** `readLines()` of the UTF-8 bytes of `café`, then
  `rng_fold()`. The result differs between UTF-8, C and ISO8859-1
  locales. Under C it equals `rng_fold(key, "caf<c3><a9>")`: the escaped
  rendering is hashed. Marked strings are fine.
- **Fix:** fold valid-UTF-8 native bytes as they are, and give a classed
  error for anything that would be escaped.
- **Family:** 4 (the third encoding value, native). **Siblings:** none;
  no other entry point hashes strings.
- **Test the suite lacked:** one string marked UTF-8, marked latin1 and
  native, under C and UTF-8 locales (#114).

## 3. Zero keys with `n > INT_MAX` give truncated dims — #124, medium, reproduced

- **Where:** `src/zurand.c:1444-1460`: the guard is `nkey > 1`, then
  `(int)n`.
- **Trigger:** `dim(rng_uniform(rng_key(42, n = 5)[0], 2^32 + 3))` is
  `3 0`. At `n = 2^31` the error is R's raw "dims contain missing values".
- **Family:** 3 (the #75 guard covers K > 1 only). **Siblings:** every
  sampler; all are affected.
- **Test the suite lacked:** zero keys with n at `INT_MAX ± 1` and
  `2^32 + 3`.

## 4. Arithmetic on keys yields other valid keys — #125, medium, reproduced

- **Trigger:** `keys + 1L`, `keys[1] - keys[1]` (the all-zero key) and
  `t(keys)` keep the class and sample without complaint.
- **Family:** 3 (`[<-` is blocked for exactly this reason; `Ops`, `Math`
  and `t` are not).

## 5. Classed scalars are read by storage value — #126, medium, reproduced

- **Where:** `src/zurand.c:403-421`.
- **Trigger:** `rng_key(factor("5"))` is `rng_key(1)`. `integer64` is read
  by its bit pattern. `Date` and `difftime` pass as numbers, on every
  numeric argument.
- **Family:** 3 (`rng_fold()` rejects classed data, #60; its siblings do
  not).

## 6. A wrapped lazy vector breaks after scan, save, scan on R 4.6.2 — #127, medium, reproduced (macOS R 4.6.2 only)

- **Trigger:** `y <- structure(rng_lazy_normal(k, 64), unit = "cm")`;
  `sum(y)`; `saveRDS(y, f)`; then `sum(y)` errors with "REFCNT on locked
  WRAPPER data increased to 2", and keeps erroring.
- **Cause:** R's wrapper class (`altclasses.c`) combined with
  `lazy_Duplicate()` returning ALTREP.
- **Family:** none. See Cross-cutting.

## Cross-cutting

- **Family 3 dominates.** Five of the thirteen findings are a guard added
  at one site and missing at its siblings: #124, #125, #126, #128 and
  #131. In each, the guard was added in response to an earlier review
  (#60, #75), and the fix did not grep for the same shape. This is the
  rule `correctness.md` already states. The hunt shows it is not yet
  habit in this package's R layer.
- **Candidate rule, a fifth family: "a host object's invariant broken
  by the package's ALTREP methods."** #127 is two correct components
  composing wrongly across a refcount invariant that neither documents.
  #122 is the same shape with the OpenMP runtime in place of R's wrapper:
  a resource the package does not own, whose rule (fork safety) it never
  states.

  Proposed wording for `correctness.md`: *"Anything the package hands to
  a runtime it does not own (R's ALTREP wrapper, an OpenMP pool, a
  libuv loop) inherits that runtime's invariants. List them (refcount,
  fork, thread, reentrancy) and test each through the runtime's own
  entry points, not ours."*

  Propose it in `pedrobtz/packages`.

## Held: what was probed and stood

- **Bit streams and transforms.** Hunter 3 wrote an independent Python
  oracle for keys, Philox, Threefry, xoshiro, uniform, ziggurat, McFarland
  and Lemire. 3 engines × 300,000 positions, plus offsets up to
  `2^53 - 20000` and C API starts up to `2^64 - 1027`: 0 mismatches.
  Rare paths hit: 16,701 wedges, 258 tails, 13,510 McFarland edges and
  1.2 million Lemire retries.
- **fdlibm port.** 160,045 arguments against 60-digit Decimal: worst
  0.84 ulp for `exp` and 0.76 ulp for `log1p`. Identical across clang,
  gcc 15 and fma-contracted builds.
- **Edge shortcuts.** 753,040 ziggurat and 191,058 McFarland boundary
  cases: 0 contradictions.
- **Equivalent routes.** SIMD on/off × 1–4 threads × all samplers ×
  3 engines, straddling the OpenMP threshold and multi-key totals across
  it. Offset, multi-key columns, C API fills, positional fills and streams
  all agree with the eager samplers.
- **R layer.** About 37 value shapes on every argument, a hostile
  session (`LC_ALL=C`, `OutDec`, `scipen`, `digits`, `warn = 2`, `TZ`),
  integer vs double, prefix stability, key methods and parallel
  dispatchers, save and readRDS. All held except #123.
- **Lazy vectors.** 3 engines × 9 kinds × 24 sizes straddling 16, 512,
  4096, 5120, 2^15 and 2^16 on every read path. Serialize and modify at
  the compare-block boundaries; copies, attributes, n up to 2^52, real
  SIGINT and time-limit interrupts, failed materialisation, single-bit
  tampering of saved states, PSOCK workers, and an ASan + UBSan build:
  all held.
- **C API.** Every invalid argument returns its documented code, with
  out untouched and the consumer never called.
- **Statistics.** 1.5e8 normals per method and engine, 1e8 integers on
  three ranges, 5e7 uniforms: p-values between 0.07 and 0.98.

## Not reached

  behaviour under LLVM's OpenMP is untested).
- #127 on R-devel, and a base-R-only reproducer for it.
- ThreadSanitizer, and concurrent C API use while `rng_simd()` is
  toggled.

- purrr, vctrs, tibble and future.apply interactions with keys.

## Not reproduced, and by design

Nothing a hunter reported failed to reproduce. These are by design:

- the same seed gives the same key words under every engine (design
  §3.1);
- a signed-zero ziggurat draw returns `+0.0` where NumPy gives `-0.0`;
- a uniform may return a bound when the span is small relative to
  `|min|` (design §3.3);
- x87/i386 output is not guaranteed (design §7);
- `fill_integer` cannot take `INT_MIN`, which is NA;
- materialisation and single-element reads are not interruptible
  (`R/lazy.R`, #77);
- engine and method arguments partially match through `match.arg()`.

## What this is

`zurand` provides stateless random numbers for R, built on the vendored
**Random123** library. Three engines: `xoshiro256pp` (the default since the
stream freeze), a hybrid in which Philox derives a fresh xoshiro256++ state for
each 512-value sub-chunk; `philox4x64` (Philox4x64-10); and `threefry4x64`
(Threefry4x64-13). Tests and generators that pin values must name their engine:
a bare `rng_key(seed)` means whatever the default is. Every value is a pure
function of an immutable key plus sampler arguments; ordinary samplers never
read or mutate `.Random.seed`.

Exported API:

- `rng_key(seed, n = 1, engine = c("xoshiro256pp", "philox4x64",
  "threefry4x64"))` creates an opaque S3 vector of keys; a key records its
  engine.
- `rng_fold(key, data)` derives one key per input key from typed data such as
  strings or whole-number counters.
- `rng_uniform()`, `rng_normal()`, `rng_integer()` and `rng_bits()` are pure
  samplers. `rng_normal(method = "mcfarland")` is McFarland's modified ziggurat,
  a second normal stream under purpose 7 (tables: `src/mcfarland_normal.h`,
  generated by `tools/generate-mcfarland-tables.py` with mpmath -- rerun, don't
  edit); the default `"ziggurat"` never changes.
- `rng_key_from_r()` is the one convenience function that intentionally consumes
  R's global RNG state.
- `rng_threads(threads)` caps OpenMP use; `rng_simd(enable)` reports (`"avx2"`,
  `"neon"` or `"none"`) or disables the vector path for `xoshiro256pp` (AVX2 on
  x86_64, NEON on arm64). Neither changes any output.

If two parts of a computation need independent random values, request a key
vector up front with `rng_key(seed, n)` or fold the parent key by structured
data.

The specification is [dev/design.md](dev/design.md) (the v1 stream: output
contract, stream specification, public surface in R and C, and the rule that
decides whether a future change is allowed), and
[dev/roadmap.md](dev/roadmap.md) orders the work in Milestones A, B and C. Both
outrank this file. **Deviation from `workflow.md`:** zurand predates the

devtools-based package (`PackageUseDevtools: Yes`). On top of them:

```sh
Rscript -e 'testthat::test_file("tests/testthat/test-zurand.R")'  # one file
Rscript -e 'devtools::clean_dll()'           # stale objects, or debug -> -O2
```

`tests/testthat/test-kat.R` and `test-golden.R` (`emit_kat.py`,

## Architecture

- **Core construction** ([src/zurand.c](src/zurand.c) plus
  [src/zurand_engine.h](src/zurand_engine.h), which `zurand.c` includes once per
  engine with `ZE_*` macros defined, so each engine gets its own monomorphic
  copy of the sampler loops without a runtime branch): counter = `{index >> 2,
  domain, purpose, tag}`, run through `philox4x64(ctr, key)`; the returned value
  is word `index & 3` of the 256-bit block, so four consecutive output positions
  share one Philox call. Public samplers use output positions `0:(n - 1)` as the
  index. The `purpose` word domain-separates bits, uniform, normal, integer and
  fold streams; preserve this if adding new counter uses. Word 3 is the engine
  tag (`ZURAND_TAG_*`, `ZE_TAG` in the engine header): 0 for philox and
  threefry, 1 for every Philox call made on behalf of `xoshiro256pp` — its
  sub-chunk seeds `{s, 0, purpose, 1}` and its retry words. Without it the
  xoshiro stream was a function of the philox stream; any new engine that
  borrows Philox needs a tag of its own. `rng_fold()` deliberately uses tag 0
  for xoshiro keys, so a seed folds to the same key words under both engines.
  Its AVX2 path runs four sub-chunks in four lanes, so it is bit-identical to
  the scalar path; `tests/testthat/test-simd.R` enforces this.
- **Keys** are integer matrices with class `rng_key`, one key per row and four
  words per key: `{k0 low, k0 high, k1 low, k1 high}`. R integers are signed and
  reserve one bit pattern for `NA`, so the C code copies key words by exact
  32-bit bit pattern with `memcpy()`. Do not replace this with ordinary integer
  coercion or NA validation; keys are opaque.
- **Sampling semantics.** Samplers default to `n = 1L`, i.e. one draw per key.
  `rng_uniform()` stuffs the top 52 bits into the mantissa of a double in `[1,
  2)` and subtracts `1 - 2^-53`, yielding exactly `(m + 0.5) * 2^-52` — strictly
  inside `(0, 1)`, with no int-to-float conversion in the hot loop. (Do not
  revert to the old `((bits >> 11) + 0.5) * 2^-53` form: the addition rounds for
  `bits >= 2^52` and can produce exactly 1.0.) `min`/`max` are applied in a
  separate pass only when non-default, like `mean`/`sd` for normals;
  `min + span * u` can round to exactly `min` or `max` when `|min|` is large
  relative to the span (about 12% of draws for `min = 1e15, max = 1e15 + 1`). `rng_normal()`
  uses a ziggurat sampler (NumPy's tables and layer layout, `src/numpyzig/`):
  the attempt-0 word from the shared block decides ~99% of draws with one table
  compare, and the rare wedge/tail paths draw more words at `(index, attempt >=
  1)` in the domain slot so draw `i` stays a pure function of `(key, i)`; keep
  `zig_normal_slow()` out of line so the fast path inlines into the fill loops
  -- `noinline` only, **never `cold`** (GCC compiles cold functions for size:
  2-5% slower normals on Zen 3), and keep fdlibm's
  `zurand_exp()`/`zurand_log1p()` `noinline` too: inlined into the slow path
  they wrecked its codegen (15-19% slower normals with Apple clang, 7-9% with
  GCC on Xeon). Only ~6% of wedge tests reach `exp()`; the fixed-point brackets
  settle the rest. **No fused multiply-add, on any compiler:** every floating
  product that feeds an addition must go through `zurand_rounded()` (or
  `zurand_rounded2()` for the two-wide scaling pass, `affine_pass()`), because
  GCC ignores `#pragma STDC FP_CONTRACT OFF` and contracts by default on arm64,
  and one fused instruction changes output by an ulp. After touching arithmetic,
  compile `src/zurand.c` with `clang -O2 -mfma -ffp-contract=fast` and confirm
  the object has no `vfmadd`/`vfmsub`; the `ubuntu-24.04-arm` R-CMD-check leg is
  the end-to-end gate. `rng_integer()` uses bounded 32-bit rejection sampling
  and returns ordinary R integer vectors. With one key, samplers return plain
  vectors; with multiple keys, samplers return an `n x length(key)` matrix,
  including a `1 x K` matrix when `n = 1`. `rng_bits(bits = 32)` returns
  uint32-as-double; `bits = 64` returns fixed-width hex strings to avoid losing
  bits in R doubles.
- **Optional OpenMP.** `src/Makevars` passes through R's
  `$(SHLIB_OPENMP_CFLAGS)`. When available, `rng_uniform()`, `rng_normal()` and
  `rng_integer()` split the whole output above a size threshold: the (key
  column, engine chunk) pairs are dealt to threads in equal contiguous runs and
  each run is filled chunk-aligned (`col_split_*` in `src/zurand.c`), so two
  keys on eight threads use eight threads, not two; values are bit-identical to
  serial output because every split falls on an engine-chunk boundary (#78).
  `rng_threads(threads)` caps zurand's thread use per session via a
  package-local count passed as `num_threads()` on each pragma (not
  `omp_set_num_threads()`, which would be process-global); every parallel region
  must carry both the `if()` size gate and `num_threads(nt)`. Worker threads
  must not call R API; samplers hoist `INTEGER(key)` into a `const int *` before
  the parallel region and workers only read that pointer and write primitive
  numeric/integer output. `rng_bits(bits = 64)` remains single-threaded because
  it creates R strings. **On a machine without OpenMP the pragmas are never
  parsed**, so a `default(none)` region missing a data-sharing clause builds
  clean locally and fails every Linux leg in CI; run `sh dev/check-openmp.sh`
  before pushing, which syntax-checks them against a stub `omp.h`.
  `src/Makevars` is generated by `./configure` from `src/Makevars.in` (and
  removed by `./cleanup`); edit the `.in` file, and mirror build-flag changes in
  `src/Makevars.win`, which Windows uses instead because it does not run
  `configure`. On macOS R leaves `SHLIB_OPENMP_CFLAGS` empty; `configure` then
  test-builds with `-Xclang -fopenmp -lomp`, which links the `libomp.dylib` R
  ships in `$(R_HOME)/lib` when the headers are installed (CRAN's build machines
  have them; locally, unpack the <https://mac.r-project.org/openmp/> tarball and
  either `sudo tar ... -C /` or point `CPATH` at its `usr/local/include`), and
  otherwise builds serially. The `macos-openmp` workflow covers the OpenMP path;
  the plain macOS R-CMD-check leg covers the fallback.
- **Huge pages on Linux.** `zurand_thp_init()` reads
  `/sys/kernel/mm/transparent_hugepage/enabled` once at load; only in `madvise`
  mode does `zurand_advise_output()` (called from the `.Call` entry points on
  the main thread, right after `Rf_allocVector`) `madvise(MADV_HUGEPAGE)`
  outputs of 4 MiB and more. Measured 2x on large fills where it applies
  (dev/simd/pagefault.c and the roadmap); in `always` mode the explicit request
  costs 6-9% (synchronous compaction), hence the mode check.
  `options(zurand.hugepages = FALSE)` disables it. Values are unaffected.
- **Performance-critical inlining.** `zurand_block` keeps the
  `R123_FORCE_INLINE` forward declaration: plain `static inline` is only a hint,
  and clang may decline it (the function is large after Philox's own forced
  inlining), leaving an out-of-line call per block whose 32-byte struct return
  goes through memory on arm64. If touching this, verify with `otool -tv
  zurand.so` that the hot sampler loops contain no call to `_zurand_block`.
  Benchmarks must be run against an `-O2` build. `devtools::load_all()` defaults
  to `debug = TRUE`, which injects `-UNDEBUG -g -O0` and measures **11x slower**
  -- 17.7 vs 195 M normals/s. Pass `debug = FALSE` and it is equivalent to `R
  CMD INSTALL`: the compile line differs only by an extra `-Wall -pedantic`, and
  measured against a fixed in-session reference the two agree to 0.2% (1.058 vs
  1.056 over three alternating rounds). Either is fine; `load_all(debug =
  FALSE)` iterates faster. If `devtools::load_all(debug = FALSE)` warns
  "Arguments in `...` must be used", nothing was recompiled and the existing
  objects were reused with whatever flags built them -- run
  `devtools::clean_dll()` first when switching from a debug build. Note `R CMD
  INSTALL .` builds in-place, so `rm src/*.o` first if you want to be certain
  nothing is reused.
- **C API for other packages.** `inst/include/zurand.h` (also on the package's
  own include path via `src/Makevars.in` and `src/Makevars.win`) defines a
  versioned, append-only table of function pointers, registered in
  `R_init_zurand` as `R_RegisterCCallable("zurand", "zurand_api", ...)`. The
  shared object is built with `$(C_VISIBILITY)` and exports `R_init_zurand`
  alone (marked `attribute_visible`; `tests/testthat/test-abi.R` asserts it):
  the table needs no exported symbol, so do not mark anything else visible. Its
  fills are the same per-key functions (`fill_uniform_key()` and friends) the
  `.Call` samplers use, so the values are the R values. Everything but `key_get`
  must stay free of R API calls — callers run them on worker threads — and
  report bad arguments as return codes, never `Rf_error()`.
  `tests/testthat/test-c-api.R` builds the fixture package
  `tests/testthat/zurandclient` against the header and compares it with the R
  samplers from inside an OpenMP loop (skipped on CRAN). Adding a member: append
  it, bump `ZURAND_API_VERSION`, never reorder. Version 2 appended
  `fill_normal_method()`; its method codes (`ZURAND_NORMAL_ZIGGURAT` = 0,
  `ZURAND_NORMAL_MCFARLAND` = 1) are defined only in the header, which
  `src/zurand.c` includes, so `rng_normal(method =)` and the C API share one
  definition. `fill_normal()` is a wrapper that passes the ziggurat; an unknown
  method is `ZURAND_EINVAL`. Version 3 appended
  `fill_uniform_at()`/`fill_normal_at()` (positions `start ..`, the C side of
  `offset =`) and `stream_uniform()`/`stream_normal()`, which call a consumer on
  the caller's thread, in order, through a caller-owned buffer, and return
  `ZURAND_STOPPED` when it asks to stop. All of them, and the column fills, loop
  over the forced-inline per-chunk functions in `zurand_engine.h`
  (`normal_chunk()`, `normal_mcf_chunk()`, `uniform_chunk()`); a range or stream
  that starts or crosses an engine chunk mid-way generates that chunk from its
  first position into a stack buffer and copies the part it needs, so values
  never depend on where a piece starts. Engine chunks differ by architecture
  (512 words; 4096 or 5120 for `xoshiro256pp`), so tests of ranges and streams
  must use offsets and chunk sizes off every boundary. There is deliberately no
  R-level callback stream: reusing one R vector across calls is the
  in-place-fill hazard of PR #4, which no API-legal reference check can rule
  out.
- **Lazy vectors (ALTREP).** [src/zurand_lazy.h](src/zurand_lazy.h), included
  once from `zurand.c` after the fills, defines the `zurand_lazy` altreal class
  behind `rng_lazy_uniform()`/`rng_lazy_normal()`. Element `i` is position `i`
  of the key's own engine, so reading every element must stay `identical()` to
  the sampler; `tests/testthat/test-lazy.R` checks every read path (Elt,
  Get_region, Extract_subset) against the materialised fill, on every engine,
  with the cache empty, after a forward walk and after a scattered miss, and
  with double indices past 2^31. The cache is one engine chunk, filled by
  `dist_chunk_key()` only when single reads walk forward; a scattered miss
  computes the value alone (`lazy_value()`). The data pointer materialises the
  whole vector once into data2 with the column fill; writable access sets
  `written`, after which serialisation stores values instead of the recipe. Only
  `Get_region` and `Extract_subset` check for interrupts; `Elt` and `Dataptr`
  must not (C and C++ callers of `REAL_ELT` cannot expect a longjmp, and R calls
  `Dataptr` with the GC off; #77). Do not add an `ALTREAL_Sum` method: matching
  R's own `sum()` of the materialised vector means reproducing its `LDOUBLE`
  accumulation across R versions and platforms, and a mismatch breaks the
  `identical()` contract (roadmap C15).
- **R ↔ C bridge.** [R/zurand-package.R](R/zurand-package.R) declares
  `@useDynLib zurand, .registration = TRUE`; entry points are registered in
  `R_init_zurand` ([src/zurand.c](src/zurand.c)) and called as `.Call(C_name,
  ...)` from the R files, one per topic: [R/key.R](R/key.R) (keys, `rng_fold()`
  and the key vector methods), [R/sample.R](R/sample.R) (samplers),
  [R/lazy.R](R/lazy.R) and [R/control.R](R/control.R) (`rng_threads()`,
  `rng_simd()`). `R_NO_REMAP` is set, so all R API calls in C must use the `Rf_`
  prefix.

## Invariants that are easy to break

Most constraints are stated where they apply, under Architecture: no fused
multiply-add, `noinline` never `cold`, opaque keys copied by bit pattern, both
OpenMP clauses and no R API on workers, the append-only C table, no interrupt
checks in `Elt` or `Dataptr`. Beyond those:

- **The stream is frozen.** Since `stream-1`, a change either leaves every bit
  unchanged or claims a new argument, purpose value or engine name (design §2,
  Milestone C). A correction to an existing stream goes through the key's
  `stream` attribute (`attr(key, "stream")`, currently 1; samplers reject
  unknown versions, and a missing attribute means 1).
- **Tests and generators that pin values name their engine.** A bare
  `rng_key(seed)` means whatever the default is.
- **Golden files are regenerated, never edited**, and only in a commit that says
  so: `tests/testthat/test-golden.R` comes from `dev/kat/emit_golden.R`.

## Testing

- **Oracles.** `test-kat.R` checks Philox, Threefry and xoshiro against the
  Python references in `dev/kat/` with exact key words; `test-golden.R` pins
  cross-platform values that every CI leg (macOS, Windows, Linux release and
  oldrel, clang, GCC, i386, musl) must reproduce; `test-digest.R` pins
  whole-stream digests of millions of draws, written to catch libm differences
  in the ziggurat's tail and wedge; `test-simd.R` checks that the SIMD path is
  bit-identical to the scalar one; `test-lazy.R` checks every ALTREP read path
  against the materialised fill; `test-c-api.R` compares the `zurandclient`
  fixture package with the R samplers from inside an OpenMP loop (skipped on
  CRAN); `test-zurngtest.R` is a PractRand smoke test through the `zurandpract`
  fixture.
- **Helpers.** One `helper-*.R` per test file that needs one (`abi`, `c-api`,
  `digest`, `kat`, `lazy`, `shortcuts`, `simd`, `zurngtest`), so the suite runs
  shuffled; `helper-state.R` has `local_threads()` and the other package-global
  settings, restored by `withr::defer`. 32-bit x87 is outside the
  reproducibility contract, and `helper-digest.R` says so.
- **Threads.** `tests/testthat/setup.R` caps the fills at two threads on CRAN,
  which allows a package's checks at most two; with `NOT_CRAN` set the machine's
  default stays, so the threaded paths run at full width.
- **CI switches.** `ZURAND_EXPECT_SIMD`, `ZURAND_EXPECT_OPENMP` and
  `ZURAND_EXPECT_ZURNGTEST` turn a skip into a failure where the path must
  exist.

## Vendored native code

`src/Random123/` (philox.h, array.h, features/, LICENSE) is copied verbatim from
upstream, <https://github.com/DEShawResearch/random123> — don't edit it; re-copy
from upstream to update. `src/Makevars` defines `-DR123_USE_MULHILO64_C99=1` as
a portable fallback for platforms without `__uint128_t`; the fast path is still
auto-selected elsewhere. `src/numpyzig/` (ziggurat_constants.h, LICENSE) is
NumPy's ziggurat table header (BSD 3-clause), **trimmed** to the normal-double
tables zurand uses (`ki_double`, `wi_double`, `fi_double`, `ziggurat_nor_r`,
`ziggurat_nor_inv_r`) and otherwise unmodified; the comment at its top records
the source and the trim. Do not reintroduce the unused float/exponential tables
or suppress their warnings with a `#pragma GCC diagnostic` -- CRAN rejects
diagnostic-suppressing pragmas. When re-vendoring, delete the same definitions
again and confirm `tools/generate-zig-bounds.R` reproduces `src/zigbounds.h`
byte for byte. `src/zurand_fdlibm.h` is **derived, not verbatim**: fdlibm's
`exp` and `log1p` (Sun, permissive notice kept in the file), which the
ziggurat's slow path uses instead of the platform libm, because Apple and
glibc/musl disagree often enough to change `rng_normal()` streams (the
whole-stream digests in `tests/testthat/test-digest.R` catch it). It is edited —
no-fusion barriers, memcpy word access — so it must be maintained by hand, never
re-copied. `src/zigbounds.h` is generated — not vendored — by
`tools/generate-zig-bounds.R` from the NumPy tables: fixed-point brackets of the
wedge test that let `zig_normal_slow()` resolve most wedge decisions without
`exp()`; rerun the script instead of editing it.

**Deviation from `native-code.md`:** the vendored trees sit at `src/Random123/`
and `src/numpyzig/`, not under `src/vendor/`, and there is no `tools/patches/`.
The NumPy trim is the one local change, and it is recorded in the comment at the
top of `ziggurat_constants.h`.
